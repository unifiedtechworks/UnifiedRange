# Data Export Plan

## Current Status

Account export is not implemented. The `/settings/account` control is a disabled placeholder and does not query, package, or download user data.

## Proposed MVP Export

The first export should be a versioned JSON document generated by a backend job for the authenticated account. It should contain:

- account-safe `UserProfile` fields, including app username and privacy preferences;
- owned equipment passports, projectile/ammo profiles, optics/sights, range sessions, target-photo metadata, maintenance records, and hunting checklists;
- owned `PublicPassportSnapshot` records;
- comments and reactions authored by the user, when permitted by the final retention policy;
- reports submitted by the user when disclosure does not expose restricted moderation information;
- a private-image inventory with stable export-relative references and metadata needed to identify the owning record.

The JSON should include export format version, generation timestamp, scope summary, and per-collection counts. It must not contain credentials, Cognito tokens, internal authorization claims, other users' private data, raw S3 keys unless required and documented, or long-lived/signed image URLs.

## Image Handling

The MVP JSON export should reference private images without embedding signed URLs. Signed URLs can expire, leak through copied exports, and do not represent durable portability.

A later ZIP export may contain the JSON document plus image files copied server-side into a temporary export artifact. That job should validate ownership for every object, use deterministic export-relative filenames, remove unsafe metadata when appropriate, encrypt at rest, and expire both artifact and download authorization after a short period.

## Secure Workflow

1. Require a signed-in user and preferably a recent/re-authenticated session.
2. Create an export job bound to the verified Cognito identity.
3. Query owner-scoped records server-side and validate every cross-record reference.
4. Generate and validate the versioned manifest.
5. Store the artifact privately with encryption and a retention expiration.
6. Notify the user that the export is ready without placing a download token in email.
7. Authorize download in-app with a short-lived, single-account mechanism.
8. Expire and delete the artifact automatically; retain only minimal job metadata.

## Public and Social Boundaries

An export can include the user's own public snapshots and authored social actions, but it must not turn readable community data into a bulk export of other users. Comment context should be limited to what is necessary to understand the user's own contribution. Report exports must not reveal moderator identities, internal notes, enforcement signals, or another person's private data.

## Completeness and Verification

- Compare exported collection counts against a server-side inventory for the same identity and snapshot time.
- Record partial failures and do not mark incomplete artifacts as ready.
- Test accounts with no data, maximum expected data, missing referenced records, deleted images, and multiple export requests.
- Version the JSON schema and document compatibility expectations.
- Ensure export generation and download events are auditable without logging artifact contents or private URLs.
